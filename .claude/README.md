# Apiiro Guardian skills — intentionally disabled (control branch)

This is the **control** side of an AutoFix A/B test. It deliberately does
**not** vendor any Apiiro Guardian skill files under `.claude/skills/`.

`.claude/settings.json` additionally disables the skills defensively, in
case they're present at the user level (`~/.claude/skills/`), a project
plugin, or an org-wide marketplace, using two mechanisms:

- `skillOverrides: "off"` — the dedicated per-skill setting; hides a skill
  from both the model and `/name` invocation.
- `permissions.deny` — explicit `Skill(...)` and `Bash(apiiro *)` deny
  rules. Deny rules are enforced even under permissive/bypass permission
  modes, and project-level settings here take precedence over user-level
  `~/.claude/settings.json`.

Covered names: guardian-fix guardian-query guardian-risks guardian-scan guardian-secure-prompt guardian-setup guardian-threat-model apiiro-guardian apiiro-fix apiiro-risks apiiro-fast-scan apiiro-diff-scan apiiro-secure-prompt apiiro-setup apiiro-threat-model.

**Known limitation:** `Bash(apiiro *)` is a string-prefix match on the
literal command, not a sandbox boundary — it won't catch invocation via an
absolute path, a shell wrapper (`sh -c "apiiro ..."`), an alias, or the
CLI's underlying API called some other way (e.g. `curl`). Treat this as
defense-in-depth, not a hard guarantee, alongside simply not installing the
skill files on this branch.

See the `autofix` branch for the counterpart with these skills enabled.
